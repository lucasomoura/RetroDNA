RETRODNA
Engenharia Reversa de Game Design Retrô → Geração de Jogos Originais

Versão 2 — Plano revisado

======================================================================
1. CONCEITO DO PROJETO
======================================================================

O RetroDNA será uma ferramenta capaz de analisar jogos retrô, inicialmente
jogos de SNES, identificar padrões de design e transformar esses padrões em
uma representação abstrata chamada DESIGN GENOME.

O objetivo NÃO é copiar um jogo.

O objetivo é descobrir características como:

- ritmo de exploração;
- ritmo de combate;
- progressão;
- distribuição de inimigos;
- distribuição de objetivos;
- frequência de recompensas;
- estrutura de mapas;
- caminhos alternativos;
- gargalos;
- curva de tensão;
- comportamento dos inimigos;
- estrutura das fases.

Depois, o Design Genome será usado para gerar uma experiência NOVA.

Exemplo:

JOGO ORIGINAL
      |
      v
OBSERVAÇÃO / ANÁLISE
      |
      v
DESIGN GENOME
      |
      v
GERADOR PROCEDURAL
      |
      v
JOGO NOVO


======================================================================
2. PRINCÍPIO FUNDAMENTAL
======================================================================

O RetroDNA não deve tentar copiar o "bolo".

Ele deve tentar descobrir a "receita".

Exemplo:

Em vez de:

"Copie exatamente esta fase."

O sistema deve descobrir:

- duração média da exploração;
- quantidade de combates;
- distribuição dos inimigos;
- distância entre objetivos;
- frequência de recompensas;
- intensidade dos encontros;
- quantidade de rotas alternativas.

Depois:

"Crie uma nova fase que siga essas características."


======================================================================
3. PRIMEIRA CORREÇÃO IMPORTANTE:
   NÃO COMEÇAR TENTANDO DECODIFICAR A ROM
======================================================================

A ideia inicial de:

ROM → extrator → JSON

parece simples, mas não é.

Jogos de SNES normalmente utilizam estruturas próprias para:

- mapas;
- tiles;
- objetos;
- compressão;
- ponteiros;
- eventos;
- gráficos;
- colisões;
- dados de gameplay.

Cada jogo pode organizar essas informações de maneira completamente
diferente.

Portanto, não existe um "extrator universal de ROM de SNES" capaz de
entender automaticamente todos os jogos.

Ferramentas genéricas de imagem ou mapas não resolvem esse problema.

Em muitos casos seria necessário:

- engenharia reversa;
- disassembly;
- análise de memória;
- identificação de ponteiros;
- identificação de estruturas;
- descoberta do algoritmo de compressão;
- interpretação do código do jogo.

Isso pode exigir semanas ou meses para um único jogo.

5. POR QUE ISSO É MELHOR PARA O MVP

Queremos que o RetroDNA seja capaz de analisar diferentes jogos.

Jogo A → código específico
Jogo B → código específico
Jogo C → código específico

Isso destrói a generalidade do projeto.

Com observação:

Jogo B → observação

A ferramenta pode trabalhar com um protocolo comum de observação.

7. ANÁLISE HÍBRIDA
======================================================================

O projeto não precisa escolher entre:

A) engenharia reversa completa

ou

B) observação completa.

Podemos utilizar as duas.

PRIMEIRA CAMADA
----------------
Observação automática.

Objetivo:
obter métricas gerais e criar o Design Genome.

SEGUNDA CAMADA
--------------
Análise de RAM.

Objetivo:
melhorar a precisão de determinadas métricas.

TERCEIRA CAMADA
---------------
Engenharia reversa seletiva.

Objetivo:
entender informações específicas que não podem ser obtidas
adequadamente pela observação.

Isso evita fazer engenharia reversa completa de cada jogo.

9. PRIMEIRA VERSÃO DO DESIGN GENOME
======================================================================

Exemplo conceitual:

{
    "gameplay": {
        "exploration": 0.72,
        "combat": 0.28,
        "objective_density": 0.35,
        "enemy_density": 0.34,
        "reward_frequency": 0.41
    },

    "level_design": {
        "average_area_size": 0.55,
        "alternate_routes": 0.62,
        "chokepoints": 0.31,
        "open_area_frequency": 0.44
    },

    "pacing": {
        "average_exploration_time": 38,
        "average_combat_duration": 14,
        "average_time_between_encounters": 52
    },

    "tension": {
        "curve": [
            0.20,
            0.35,
            0.70,
            0.45,
            0.80,
            0.90,
            0.40
        ]
    }
}


DEFINIÇÕES DE PACING (v2.1):
- average_combat_duration: duração média de um encontro (início até fim).
- average_exploration_time: tempo médio entre o FIM de um encontro e o INÍCIO do próximo.
- average_time_between_encounters: tempo médio entre o INÍCIO de dois encontros seguidos.
  Consistência obrigatória: between_encounters ≈ exploration_time + combat_duration
  (no exemplo: 38 + 14 = 52; combate/(combate+exploração) = 0,27 ≈ combat 0,28).

======================================================================
10. UMA REGRA IMPORTANTE SOBRE A IA
======================================================================

A IA NÃO deve inventar métricas.

Se o sistema mediu:

average_combat_duration = 14 segundos

a IA pode interpretar:

"Os combates tendem a ser curtos."

Ela não pode transformar isso em:

"Os combates duram aproximadamente 20 segundos."

sem uma fonte ou cálculo adicional.

Separar:

DADO
INTERPRETAÇÃO
HIPÓTESE

será uma regra fundamental do RetroDNA.


======================================================================
11. PAPEL DA IA
======================================================================

A IA será principalmente responsável por:

- interpretar dados;
- encontrar padrões;
- gerar relatórios;
- identificar relações;
- sugerir hipóteses;
- transformar métricas em regras de design;
- criar especificações para o gerador.

Ela NÃO será a responsável primária por medir o jogo.


======================================================================
12. CURVA DE TENSÃO
======================================================================

A curva de tensão provavelmente será um dos elementos mais importantes
do Design Genome.

Porém, "tensão" não é uma variável diretamente disponível na RAM.

Precisamos criar uma definição operacional.

Inicialmente podemos usar indicadores como:

- quantidade de inimigos;
- proximidade de inimigos;
- frequência de dano;
- quantidade de projéteis;
- quantidade de obstáculos;
- tempo desde a última recompensa;
- quantidade de objetivos ativos;
- disponibilidade de rotas de fuga;
- duração do combate.

Esses fatores podem gerar um índice aproximado de tensão.

Exemplo:

Tensão =
    inimigos
  + proximidade
  + risco
  + duração do combate
  - segurança
  - recompensa


A fórmula inicial será experimental.

Depois poderá ser calibrada através de testes.

======================================================================
25. QUESTÃO DE DIREITOS AUTORAIS
======================================================================

O projeto deve ser desenvolvido com uma separação clara entre:

MATERIAL DE ANÁLISE

e

CONTEÚDO FINAL.

A ferramenta pode estudar características de um jogo, mas o resultado
final deve ser criado como conteúdo novo.

Não distribuir:

- ROMs;
- sprites originais;
- mapas originais;
- músicas originais;
- efeitos sonoros originais;
- personagens protegidos;
- fases reconstruídas;
- outros assets protegidos.

Também não devemos presumir que qualquer técnica de extração ou uso
é automaticamente permitida.

A legislação aplicável pode variar conforme o país e o contexto.

Para um produto comercial ou distribuição pública, será importante obter
orientação jurídica específica.


======================================================================
26. O QUE O GENOME NÃO DEVE CONTER
======================================================================

Evitar armazenar:

- sprites;
- texturas originais;
- música original;
- áudio original;
- mapas reconstruídos;
- código original;
- nomes protegidos;
- conteúdo visual copiado.

O Genome deve representar propriedades abstratas e métricas.

33. DEFINIÇÃO DO RETRODNA
======================================================================

RetroDNA não é:

"uma IA que copia jogos antigos."

RetroDNA é:

"uma ferramenta de engenharia reversa de game design que observa,
analisa e abstrai padrões de jogos existentes, transformando-os em
um Design Genome capaz de orientar a geração procedural de novas
experiências."
